# panel の図 (SVG と marks の動き) で説明する

panel のまとめのペインで、状況・流れ・手順・比べる案・ユーザーにしてほしいこと (どこを見て何を押すか) を説明するときは、
**まず図で描く**。文は、図の上の「いま」、図の下の 1 行の説明 (caption)、図に描けないこと (条件・例外・写して打つコマンド) に
留める (ユーザーの指示 2026-11-18: 文字だけの説明にしない。下の「1 枚の形」の手本の図を見習い、動く図を使う)。「いま」と
図に描けないことは、太字の見出しの項目を親にし、詳細をその下に一段下げた箇条書きにする (ユーザーの指示 2026-11-19)。見出しの
項目は「いま」が 1〜3 つ・図に描けないことが 3〜5 つで、それぞれの下に詳細を 1〜3 行 (下の「箇条書きの形」)。

panel.json の欄と marks の種類の正は mod の `main.js` の頭のコメント、図の置き場所と書く手は `panel.md` の「置き場所」「図」。
ここは、何を図にするか・1 枚の形・色・動きの置き方・雛形 (`assets/panel/`) の使い方。図を会話のチケットにも残す手は、Dev Tracker を
使うホストの足し分の skill `pjp-hc-hub-private` (skill の一覧にあれば) の手。

## 図にするもの・文で足りるもの

| 見せるもの | 形 |
| --- | --- |
| ユーザーにしてほしいこと (どこを見て何を押すか・確かめの手) | 手順ごとに 1 枚 (雛形 act)。押す所に番号 ① ② と pulse |
| 状況 (何と何がどうつながり、どこで止まっているか) | 登場物の箱と通り道 (雛形 act から、ユーザーがする所を消す) |
| 流れ・届く道筋 (merge から当てるまで・設定が届くまで) | 段を上から並べる (雛形 route)。いまの段を色で分ける |
| 比べる案・前と後 | 左右に並べる (雛形 compare)。案の名前と並びは問いの選択肢と同じにする (推す案が左) |
| 子の進み具合・PR (段・状態・リンク。チケットがあればチケットも) | 進み具合の木の節 `work` (`panel.md` の「チケット・進み具合・PR」。`work` を知らない mod では flow と一覧の節 `prs`・`tickets`)。図にしない |
| 箇条書きの項目のうち複雑なもの (流れ・前と後・分岐・3 つ以上がかかわる) | その項目の詳細の下にミニ絵 (下の「ミニ絵」。雛形 mini-flow・mini-before-after・mini-branch)。1 回の書き直しで 3 枚まで |
| 場面を順に流す説明・押して案を見比べる見本 | panel には出さない (panel の image は静止画で、SVG の中の JS も SMIL も CSS の動きも動かない)。scratchpad に 1 ファイルの HTML で作り、panel の「いま」にその場所を 1 行書く (`panel.md` の「図」) |

次のどれかに当たるときは、図を描かずに文 (markdown の節) で書く:

- 1〜3 行で済む知らせ (子が PR を出した・CI が通った・merge した・次は何か)。進み具合の木の行と段も進める
- 写して使う字 (コマンド・パス) と、押して開くリンク (URL)。SVG の字は選べず写せず押せないので、markdown の節に書く (字は
  code の span、リンクは `[字](URL)`。`panel.md` の「書き方」)。PR (チケットがあればチケットも) は進み具合の木に行で足す
- 登場物が 2 つ以下で、流れも順番も無いこと
- その往復だけの一時の知らせ (「撮っています」など)

markdown の節は 1 つに見出しの項目 5 つまで (詳細はそれぞれ 1〜3 行。1 行 1 文)。それを超える中身は図にするか、scratchpad の
ファイルに書いて panel から外す (panel には場所を 1 行)。

### 箇条書きの形

markdown の節の箇条書きは、太字の見出しの項目を親にし、詳細はその下に空白 2 つで一段下げた子の項目にする (ユーザーの指示
2026-11-19)。見出しの項目は名詞の短い句 (`**畳み方**`・`**あなたに頼むこと**`) で、詳細は 1 行 1 文。

```markdown
- **畳み方**
  - Done・Canceled で、下に動いているものが無いチケットは 1 行に畳む
  - 動いているチケットは開いて出す
- **データ**
  - 新しい節の type work
```

- panel.json の text では、改行を `\n` に、下げを空白 2 つにする (`"- **畳み方**\n  - Done・Canceled で、…\n  - 動いている…"`)。
  Windows のハブの panel で、親が「•」、子が「◦」で一段下がって出た (2026-11-19。mod は直さずに出る)
- 「見出し: 詳細」を 1 行に詰めた形 (`- 畳み方: Done・Canceled で、…。動いているチケットは開いて出す`) は、見出しを太字の親に、
  `:` の後ろの文を 1 文ずつ子に分けて書き直す
- 複雑な項目には、詳細の最後の行の後ろにミニ絵の行 (`  ![説明](<会話の名前>/mini-<名前>.svg)`) を足せる (下の「ミニ絵」・`panel.md` の「ミニ絵」)

### 手間の線

- 雛形を写し、字・色・箱の数を替えて描く。それで描ける図 (1 枚 5 分ほど) は惜しまず描く
- 雛形から遠い形 (木・地図・時刻の並び) を一から描くのは、ユーザーが手を動かす手順のときと、2 往復以上続く話のときだけ。
  それ以外は、雛形の箱と線に言い換えて描く
- 1 つの話に図は 3 枚まで。手順が 4 つ以上なら、今の手順と次の手順の図だけを開いて出し、済んだ手順の図は
  消さずに `done: true` と `collapsed: true` を付けて下へ移す (mod が小さく畳んで出す。`panel.md` の「済んだものを残す (小さく畳む)」)
- 描き直すのは、図の中身が変わったときだけ。押す所が済んだだけなら pulse を外す。何度も替わる字 (件数・時刻) は、初めから
  SVG に描かずに label の mark で置いておけば、label だけを替えて済む (下の「動きの置き方」)

## 1 枚の形

手本はハブの図「R1 中継を通して承認する (① ②)」(雛形 act はこの形。`assets/panel/act.svg`):

| 段 | 中身 (R1 の字。`/` は箱の中の改行) |
| --- | --- |
| 上 | ユーザーがする所 2 つ (黄・点滅):「op-reason の窓 (右上) / ① この呼び出しを許可」「1Password の画面 / ② 認証 / Windows Hello」。点線で下の登場物へ |
| 中 | 登場物 3 つを左から:「端末 A / 中継を通す ssh / 中継のパイプへ」→「中継 / op-reason.exe / 中継のタブで動く」(主役・青) →「1Password / SSH agent / いまはロック中」(3 行目が黄)。間の線に「依頼」のラベルと流れる点 |
| 下 | 見ること:「・1Password の画面に出るアプリの名前 (S12 では herdr-app)」「・ssh が通れば R1 は済み。私が続けて R2 を打つ」 |
| 図の下 | caption:「私が端末 A から中継を通して ssh を打つ。依頼は中継を通って 1Password へ行く」 |

- **登場物は箱**。3 行で書く: 名前 (13〜14 px・太字)・役目 (12 px)・今の状態 (11 px。灰か、状態の色)
- **主役 (その図で一番見てほしい登場物) は青**。1 枚に 1 つ
- **ユーザーがする所は黄の箱**。1 行目に場所 (どの窓・画面か)、2 行目に番号と動作 (15 px・太字)。かかわる登場物の箱へ点線を引き、
  pulse を重ねる。断る・取り消す操作 (手本の R2 の「③ 拒否を押す」) は赤の箱にする
- **番号 ① ② ③ は手順の通し番号**。図・節の title・問いの選択肢・返答の文で同じ番号を使う (title の例「R1 中継を通して承認する (① ②)」)
- **依頼やデータの通り道は線と flow の点**。線は灰 (2 px)、点は通り道の色。線の上に小さく「依頼」などのラベル (10 px)
- **使わない道・通らない箱は灰の点線**。字も灰にし、「通らない」と書く (手本の R2 の、中継をくぐって直につなぐ図)
- **図の中に「見ること」の箱**: ユーザーが見て確かめる所と、済んだら次に起きること (2〜3 行)。結果が分かれるなら「どちらになるか」の
  箱にし、行の色で分ける (緑 = 思ったとおり・赤 = 違った)
- **手順ごとに 1 枚**。1 枚に全部の手順を詰めない
- **どこを見るか・どこを押すかの図は、画面の並びどおりに箱を置く** (ペイン・窓・ボタンの位置。上のペインは上に)。雛形 act の
  横並びは、依頼の通り道を見せるときの並び
- **図の下に 1 行の caption**: 誰が何をして、何がどこへ行くか。caption にリンク (URL) は書かない (panel が URL を確かめてから開く
  扱いの外。リンクは「いま」などの markdown の節に書く)
- 凡例は描かない (色を役割で揃えれば要らない)。どうしても要るなら、図の下端に 1 行

## 動きの置き方 (marks)

panel で動くのは marks だけ (SVG の中の SMIL・CSS・JS は動かない)。動きは意味のある所にだけ付ける: 流れ = flow、ユーザーがする所 =
pulse、行き来 = dot。比べる図のように、流れもユーザーがする所も無い図は止まっていてよい (marks は空)。

- **flow** (一方向に流れる点): 通り道の線と同じ x1,y1 → x2,y2 に置く (向きは依頼・データの向き)
  - 線は**横か縦で、40〜60 px** にする (箱の間の距離。手本は 42 px)。点は半径 292 の輪の弧を走るので、中点から 25 px より先では
    線から外れて欠け、70 px より先では消える。斜めの線は切り抜きが線を囲む矩形になるので、点が線の端から箱へはみ出し、長い
    斜めでは線から大きく外れる。40 px より短いと、点が 1 つも見えない間ができる
  - 長い通り道は、線は 1 本のまま、flow を 40〜60 px ずつに割って端をつないで並べる (204 px の線なら 51 px の flow を 4 本。
    panel で、点が欠けずに 1 本の流れに見えると確かめた 2026-11-18)。斜めの通り道は、横と縦の線に分けて描く
  - speed は 32 (手本)。点の間は約 41 px で、40〜60 px の線には 1〜2 個が見える
  - color は通り道の色 (主役へ向かう道は `#61afef`、くぐる道は `#d19a66`)
- **pulse** (点滅する枠): ユーザーがする所の箱の rect と同じ x・y・w・h・radius (rx)。color は箱の枠の色
  - 1 枚に 2 つまで。済んだら外す (図は替えなくてよい)。主役や推す案には付けない (点滅は「あなたの番」の印)
  - 付けるのは今の番の手順の図だけ。次の手順の図の黄の箱は点滅させず、番が来たら marks に足す
- **dot** (行って戻る点): 行き来 (問い合わせと返事・見回り・つながっているか) を見せるとき。向きのある流れは flow
- **label** (字): SVG を描き直さずに替えたい字 (件数・時刻・「済んだ」)。label は背景の無い字を重ねるだけで、下の SVG の字を
  隠せない。替える字は SVG に描かずに空けておき、初めから label で置く (SVG に描いた字を替えるなら、名前を替えて描き直す)。
  x,y は字の左上 (SVG の text の y は字の下の線)。9 px より小さくならない。`pjp hub bake` の写しには焼いた時点の字が入り、
  後で label を替えても写しは替わらない
- marks の座標は表に出る大きさの px (節の width・height と、SVG の viewBox と同じ空間。下の「細かさ」)。図が縮めば marks も同じだけ縮む
- panel の外で動かして見せる写しは、`pjp hub bake` が marks を SVG の中の CSS の動きに焼く (flow は線の上を流れる点・pulse は点滅する枠・
  dot は行き来する点。`panel.md` の「図」)。panel に載せる SVG に CSS や SMIL の動きを書き足さない (panel では動かず、焼いた写しでは
  marks と二重になる)

## 大きさと字

大きさと字の px は、どれも表に出る大きさ (SVG の viewBox の単位) で書く。SVG の根の width・height は、その 4 倍にする (下の
「細かさ」)。

- 幅は **460**。panel は図をペインの幅 (余白の 50 px を引き、アプリの zoom で割った幅) に合わせて縮め・大きくする (0.1〜2 倍。
  dotfiles #255 の mod から)。広く描くほど、同じペインで字が小さく出る。手本も、540 で描いた図を 460 に詰め直して載せた (前の
  mod (縮めるだけ) で、460 の雛形はハブのまとめのペインに縮まずに出た 2026-11-18)
- ユーザーは図をクリックすると、図だけを大きく出す小窓 (窓の幅の 92%・高さの 90%。図は 4 倍まで大きくなり、marks も動く) で
  見られる。それでも、まとめのペインのままで読める字の大きさ (下の「字」の px) で描き、小窓を当てにして細かく描き込まない
- 高さは 220〜360。図 1 枚が、まとめのペインの 1 画面に収まる高さにする (問いのペインを開くと、並びによってはまとめのペインが
  低く・狭くなる。並びは `panel.md`)
- 字: 名前 13〜14 (入れ物の中の部品は 12)・役目 12・状態と補足 11・線のラベル 10・ユーザーの動作 15 (太字)。10 px より小さくしない
  (ミニ絵も同じ。`pjp hub bake` が、表に出る図で 10 px より小さい字を `!!` の行で知らせる。下の「確かめる」)
- 1 行の長さ: 幅 120 の箱で、12 px の行は全角 9 字まで。長い名前は 2 行に割らず、短く言い換える
- 外周の余白は 8 px ほど (6〜14)、箱の間は 40〜60 px (flow の線の長さ)。座標は整数で書き、箱の中の字は `text-anchor="middle"` で
  中央に置く
- font-family は雛形のまま (`'Yu Gothic UI', 'Meiryo UI', Meiryo, 'Segoe UI', sans-serif`。名前を引用符で囲む。`panel.md` の「図」)
- Yu Gothic UI は `\` を `¥` の形で描く (panel で確かめた 2026-11-18。`~` はそのまま。Meiryo も同じで、`tspan` で Segoe UI を
  指しても戻らなかった (Windows の字体を resvg に渡した下見))。図に Windows のパスを書くときは `/` で区切る
  (`mods/pjp-hub-panel/`)。写して打つパスは図に書かず、markdown の code の span に書く

## 細かさ (SVG の根の width・height)

panel の図 (image の節の SVG とミニ絵) は、表に出る大きさを viewBox に書き、SVG の根の width・height をその **4 倍** にする
(ユーザーの指示 2026-11-28: panel の図が粗くて読めないので、3 倍以上に細かくする。ミニ絵も
4 倍にそろえるのは、同じ日のユーザーの答え)。倍率はここにだけ書く。雛形
(`assets/panel/`) と `pjp hub bake` (dotfiles の `nix/pkgs/pjp-tools/crates/pjp-hc-hub/src/bake.rs` の `FINENESS`) はこの数に合わせる
(bake の試験が、雛形の根の大きさとこの節の数を `FINENESS` と突き合わせる)。

| 図 | 表に出る大きさ (viewBox) | 根の width・height | panel が大きく出す上限 |
| --- | --- | --- | --- |
| image の節 | 節の width・height (雛形は 460×300 など) | 4 倍 (460×300 なら 1840×1200) | ペインで 2 倍・小窓で 4 倍 |
| ミニ絵 | 200×80 | 4 倍 (800×320) | ペインの幅いっぱい (ふだんのペインで 4 倍ほど)・小窓で 8 倍 |

```xml
<svg xmlns="http://www.w3.org/2000/svg" width="1840" height="1200" viewBox="0 0 460 300" …>   <!-- image の節 (width 460・height 300) -->
<svg xmlns="http://www.w3.org/2000/svg" width="800" height="320" viewBox="0 0 200 80" …>      <!-- ミニ絵 -->
```

- 座標・字の大きさ・地の rect・marks は、今までどおり表に出る大きさ (viewBox の単位) で書き、根の 2 つの数だけを 4 倍にする。雛形を写せば、
  もう 4 倍になっている。字・箱を描き替えても根の 2 つの数は替えない
- 4 倍にするわけ:
  - herdr-app の `image()` (GPUI の img()) は、SVG を根の width・height の 2 倍で 1 回だけ絵 (bitmap) にし、あとは引き伸ばして描く
    (mod の頭のコメントの「図の大きさと、大きく見る小窓」)。絵にする倍率を渡す口は無い (herdr-app の `gpui-kit.d.ts` の `image(path)`)
  - 表に出た図には、アプリの zoom (ユーザーは 1.1) と画面の表示の倍率 (4K の画面で 150%) が掛かる。表に出る大きさの n 倍で出た図は、
    n × 1.65 倍の実の px になる。根を 4 倍にすると絵は 8 倍で、n が 4.8 までを覆う (image の節の小窓の 4 倍 → 6.6 倍、ミニ絵のふだんのペインの
    幅 (画面の約 800 px) → 4 倍ほど)
  - 根が表に出る大きさのまま (2026-11-28 までの決まり) だと絵は 2 倍しかなく、小窓では 3.3 倍に引き伸ばしてにじみ、字が読めなかった
- ミニ絵は、mod が置き場の幅いっぱいの 16:9 の枠に収まるいっぱいで出し (下の「ミニ絵」)、小窓で 8 倍まで大きくする。小窓で 8 倍
  (画面の約 2640 px) まで大きくしたときと、ペインを窓いっぱい (`pane.zoom`) にしたときは、絵を 1.65 倍ほどに引き伸ばし、字の縁が少し
  柔らかい。ユーザーはそれを受けて 4 倍にそろえた (2026-11-28。試しのペインで 8 倍と見比べ、4 倍で足りるとした。決まりが「図は全部 4 倍」の 1 つで
  済み、絵の重さも 1 枚 16 MB から 4 MB になる)
- 重さ: 460×300 の図は 3680×2400 px の絵 (約 35 MB)、ミニ絵は 1600×640 px (約 4 MB) になる。1 回の書き直しで載せる図の枚数の決まり
  (1 つの話に 3 枚まで・ミニ絵は 3 枚まで) は変えない
- 粗い図 (根が表に出る大きさの 4 倍より小さい)・縦横の比が表に出る大きさと違う図は、`pjp hub bake` が `!!` の行で知らせる (「確かめる」)。
  4 倍より細かい図は知らせない
- `pjp hub bake` の写しは、根の width・height を表に出る大きさに戻して書く (panel の外では今までどおりの大きさで出る。SVG は図形のまま
  描かれるので粗くならない)
- 前の決まりで描いた図 (根が表に出る大きさのまま) を細かくするときは、図を Read で読み、根の width・height だけを 4 倍にした写しを
  別の名前 (`<名前>-x4.svg`) で Write し (viewBox が無ければ、元の表に出る大きさで `viewBox="0 0 <幅> <高さ>"` を足す)、panel.json の
  節の src・ミニ絵の行のパスを写しに替える (同じ名前で書き換えた図は描き直らない)。節の width・height と marks はそのまま。字が 10 px
  より小さい図は、細かくしても読みにくいので、雛形から描き直す。panel の外に出した写しは出し直さなくてよい (写しは粗くない)

  上に置く。その上に Q&A を置くのはユーザーの指示 2026-11-23)。`work` を知らない mod (`panel.md` の「当てる順と、古い mod のとき」) では `work` を置かず、図に描けない
  ことの後ろ (前の話の前) に子の進み具合 (flow) → PR の一覧 (`prs`) → チケットの一覧 (`tickets`。チケットのあるハブだけ) を置く
- 済んだ話の図は panel.json から消さず、`done: true` と `collapsed: true` を付けて前の話として下へ移す (ユーザーの指示 2026-11-27。
  mod が小さく畳んで出す。`panel.md` の「済んだものを残す (小さく畳む)」)。新しい mod (`済んだもの: True`) では、version を替えなくても書いた
  時点で畳まれる (もう出ている節にも効く。ユーザーが手で開けた節は開いたまま)。古い mod (`済んだもの: False`) は collapsed を、初めて
  読んだときと version を替えたときにしか読まない (`panel.md` の「書き方」と「当てる順と、古い mod のとき」)。ユーザーが × を付けた図は、次に書くときに外す
  (`panel.md` の「節を消す印 (×)」)

## ミニ絵 (項目の下の小さな図)

箇条書きの複雑な項目の下に出す小さな図 (書き方・付ける項目・置き場所・使える mod は `panel.md` の「ミニ絵」)。雛形を写し、字だけを
替えて描く (ユーザーの承認 2026-11-19)。

- 形は幅 200・高さ 80 だけ (`viewBox="0 0 200 80"`。根は `width="800" height="320"`。上の「細かさ」)。panel は、置き場の幅 (項目の字の
  頭からカードの右の縁まで) いっぱいの 16:9 の枠に収まるいっぱいで出す。5:2 は 16:9 より横長なので、右の端が置き場の右の縁に届く。
  ペインの幅と panel の文字の倍率 (− % +) に追う (ユーザーの指示 2026-11-28: 16:9 の枠に収めたときに右の端が縁に届くまで大きく
  出し、panel の拡大・縮小に追う。それまでは 200×80 を文字の倍率で変えた 1 つの大きさ (100% で 240×96)。`panel.md` の
  「ミニ絵」)。大きく出るぶん、字は今までどおり 10 px 以上で、詰め込まない
- 字体・色・地の rect は今の図と同じ (上の「色」「大きさと字」)。字は 10 px 以上 (viewBox の単位)
- 形は少なく、箱 2〜3 つと矢印まで。字は箱ごとに 2 行まで (名前と状態か補足。図全体で 6 行まで)。箱の字は全角 8 字まで (半角は
  2 字で全角 1 字)。雛形ごとの上限は下の表 (雛形の SVG のコメントにもある)。箱・字の行を足したくなったら、ミニ絵でなく image の節の図にする
- 動き (marks) は付けない。説明の字はミニ絵の下に出ないので、図の中の字だけで分かるように描く

| ファイル | 形 | 箱の字の上限 (全角) |
| --- | --- | --- |
| `assets/panel/mini-flow.svg` | 段 A → 段 B → 段 C (済んだ = 緑・いま = 青・まだ = 灰) | 名前 4 字・状態 5 字 |

1. 雛形を Read で読み、字だけを替える。色は「色」の表の役割で替えてよい (分かれた先を緑 = 思ったとおり・赤 = 違った、など)
2. `<home>\pjp-hub-panel-media\<会話の名前>\mini-<名前>.svg` に Write で書く。描き直したら名前を替える
3. 確かめる。形を変えたときだけ絵にして見る (token を抑えるため):
   - 字だけを替えた: XML として読めるか (`panel.md` の「図」の 1 行) と、箱ごとの字数が上の表の上限に収まるかを数える
   - どちらでも: panel.json に絵の行を書いた後、`pjp hub bake '<panel.json の絶対パス>' <会話の名前>/mini-<名前>.svg --out '<scratchpad>\bake-check'`
     で写しを作り、`!!` の行を見る。粗い (根が 4 倍より小さい)・字が 10 px より小さい・箱が 4 つ以上・字の行が 7 行以上なら、雛形から
     描き直し、名前を替えて載せ直す
   - 形を変えた (箱を足した・動かした・大きさを替えた): 次の script で headless Edge に絵にさせ (根の大きさの 800×320)、Read で見る。字が箱からはみ出さないか、矢印が箱に届くか

```powershell
# 埋めるもの: <ミニ絵の SVG の絶対パス>・<png の絶対パス> (scratchpad。panel のフォルダの外)
$edge = (Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\App Paths\msedge.exe').'(default)'
$ud = Join-Path $env:TEMP "pjp-mini-edge-$PID"   # 使い捨ての profile (ユーザーの Edge の profile と窓に触らない)
& $edge --headless --disable-gpu --hide-scrollbars --no-first-run --no-default-browser-check "--user-data-dir=$ud" --window-size=800,320 --force-device-scale-factor=1 '--screenshot=<png の絶対パス>' ([uri]'<ミニ絵の SVG の絶対パス>').AbsoluteUri 2>$null | Out-Null
Remove-Item -Recurse -Force $ud -ErrorAction SilentlyContinue
Test-Path '<png の絶対パス>'   # True なら絵ができた
```

- msedge.exe も herdr-app と同じく GUI の exe なので、`| Out-Null` で流して待つ (`panel.md` の冒頭の「流して待つ」)。`2>$null` は
  Edge が出す sync などの ERROR の行を捨てる。この形 (前の大きさの `--window-size=200,80 --force-device-scale-factor=2`) を Windows の
  pwsh 7 で流し、待った直後に png があり、使い捨ての profile が消えたことを確かめた (2026-11-19)。Edge は SVG を根の大きさで開くので、
  窓は根の 800×320 にし (窓が小さいと左上だけが写る)、等倍で撮る (png も 800×320)
- 3 つの雛形の字を、全角の上限まで入れた写しをこの手で絵にし、どの箱でも字が箱に収まると確かめた (2026-11-19。Windows の
  Yu Gothic UI。根を 4 倍にしても viewBox の中の字と箱の比は変わらない)

## 確かめる

1. XML と JSON として読めるか (`panel.md` の「書き方」「図」の 1 行ずつ)
2. marks が図の箱と線に合っているか (次の script。`ずれ` の行を、出たわけのとおりに直す)
3. shot で見る (`panel.md` の「見た目を確かめる」)。2 枚で点が線に沿って動くか、点滅の枠が箱に重なるか、字が箱からはみ出さないか
4. `pjp hub bake` で写しを作るときの `!!` の行 (焼けない mark・theme の名前の色・節と SVG の縦横の比の違い・粗い図 (根が「細かさ」の
   倍率より小さい)・表に出る図で 10 px より小さい字・箱か字の行の多すぎるミニ絵) も、panel の図のずれと読みにくさの合図。panel.json か
   SVG を直す (`note:` の行は知らせだけ)

```powershell
# 埋めるもの: <SVG の絶対パス>・<panel.json の絶対パス>・<節の id>
$fine = 4   # 根の width・height は viewBox の何倍か (panel-figures.md の「細かさ」)
$svg = [xml](Get-Content -Raw '<SVG の絶対パス>')
$sec = @((Get-Content -Raw '<panel.json の絶対パス>' | ConvertFrom-Json).sections | Where-Object { $_.id -eq '<節の id>' })[0]
$rects = @($svg.SelectNodes("//*[local-name()='rect']"))
$lines = @($svg.SelectNodes("//*[local-name()='line']"))
$root = $svg.DocumentElement
$w = $root.width; $h = $root.height
$vb = @("$($root.viewBox)".Trim() -split '[\s,]+')
if (-not $sec) { "ずれ  節 '<節の id>' が panel.json に無い" }
elseif ($vb.Count -ne 4 -or "$($vb[2])" -ne "$($sec.width)" -or "$($vb[3])" -ne "$($sec.height)") {
  "ずれ  viewBox: SVG '$($root.viewBox)' / 節 $($sec.width)x$($sec.height) (viewBox は 0 0 <節の width> <節の height>)" }
elseif ("$w" -ne "$($fine * $sec.width)" -or "$h" -ne "$($fine * $sec.height)") {
  "ずれ  細かさ: 根 ${w}x$h / 節の $fine 倍 $($fine * $sec.width)x$($fine * $sec.height) (「細かさ」)" }
else { "ok    大きさ 節 $($sec.width)x$($sec.height)・根 ${w}x$h" }
$on = { param($l, $px, $py)   # 点 (px, py) が線 l の上 (0.5 px まで) にあるか
  $ax = [double]$l.x1; $ay = [double]$l.y1; $dx = [double]$l.x2 - $ax; $dy = [double]$l.y2 - $ay
  $dd = $dx * $dx + $dy * $dy
  if ($dd -eq 0) { return $false }
  $t = (($px - $ax) * $dx + ($py - $ay) * $dy) / $dd
  ($t -ge -0.001) -and ($t -le 1.001) -and ([math]::Abs($dx * ($py - $ay) - $dy * ($px - $ax)) / [math]::Sqrt($dd) -le 0.5) }
foreach ($m in $sec.marks) {
  if ($m.kind -eq 'pulse') {
    $hit = @($rects | Where-Object { [double]$_.x -eq $m.x -and [double]$_.y -eq $m.y -and [double]$_.width -eq $m.w -and [double]$_.height -eq $m.h })
    $r = if ($null -ne $m.radius) { [double]$m.radius } else { 8 }   # mod は radius が無ければ 8
    $why = if (-not $hit) { '同じ x・y・幅・高さの rect が無い' }
           elseif ([double]$hit[0].rx -ne $r) { "radius ($r) が rect の rx ($($hit[0].rx)) と違う" }
           elseif ($hit[0].stroke -ne $m.color) { "color ($($m.color)) が rect の枠の色 ($($hit[0].stroke)) と違う" }
    if ($why) { "ずれ  pulse $($m.x),$($m.y) $($m.w)x$($m.h): $why" } else { "ok    pulse $($m.x),$($m.y) $($m.w)x$($m.h)" }
  } elseif ($m.kind -eq 'flow') {
    $len = [math]::Round([math]::Sqrt([math]::Pow($m.x2 - $m.x1, 2) + [math]::Pow($m.y2 - $m.y1, 2)))
    $why = if (-not ($lines | Where-Object { (& $on $_ $m.x1 $m.y1) -and (& $on $_ $m.x2 $m.y2) })) { '線の上に無い' }
           elseif ($m.x1 -ne $m.x2 -and $m.y1 -ne $m.y2) { '斜め (横と縦の線に分ける)' }
           elseif ($len -gt 60) { "$len px (60 px までに割って並べる)" }
           elseif ($len -lt 40) { "$len px (箱の間を 40 px 以上にする)" }
    if ($why) { "ずれ  flow $($m.x1),$($m.y1) -> $($m.x2),$($m.y2): $why" } else { "ok    flow $($m.x1),$($m.y1) -> $($m.x2),$($m.y2)" }
  }
}
```

## よくある誤り

| 誤り | 直し方 |
| --- | --- |
| 文の節を先に書き、図を後から足す (文が長いまま残る) | 図から描き、文は図に描けないことだけにする |
| 箇条書きの 1 行に「見出し: 詳細」を詰める (`- 畳み方: …。…`) | 見出しを太字の親の項目にし、詳細は 1 文ずつ空白 2 つで下げた子の項目にする (「箇条書きの形」) |
| ミニ絵の行を項目の詳細の途中に挟む・後ろに続きの文 (項目でない行) を書く (続きの文は左の端からの別の文として出る) | ミニ絵の行は、項目の詳細の最後の行の後ろ (次の見出しの項目の前) に置く (`panel.md` の「ミニ絵」) |
| 文で足りる項目にもミニ絵を付ける・1 回の書き直しで 4 枚以上 | 複雑な項目 (流れ・前と後・分岐・3 つ以上がかかわる) だけに、3 枚まで |
| 1 枚に全部の手順を詰める | 手順ごとに 1 枚。節の title に手順の名前と番号 |
| 幅 540 以上で描く (ペインで縮み、字が潰れる) | 幅 460 で描く |
| 根の width・height を表に出る大きさのまま (`width="200" height="80"`) にする (大きく出るとにじむ) | 根は viewBox の 4 倍 (「細かさ」)。雛形を写せばそうなっている |
| ミニ絵に箱と字の行を詰め、字を 10 px より小さくする (表の上でも小窓でも読めない) | 箱 3 つ・字の行 6 行・字 10 px 以上に収める。収まらなければ image の節の図にする |
| 長い線・斜めの線に flow を 1 本 (点が中ほどにしか出ない・線から外れる) | 40〜60 px に割って並べる。斜めは横と縦に分ける |
| pulse を主役・推す案・大事な箱に付ける | pulse はユーザーがする所だけ |
| 箱を動かして marks を直し忘れる | 確かめの script で `ずれ` を見る |
| 同じ名前の SVG を書き換える (描き直らない) | 名前を替える (`x.svg` → `x-2.svg`) |
| 写して打つコマンドを SVG に書く (選べず写せない) | markdown の節の code の span に書く |
| URL を SVG や caption に書く (SVG の字は押せない。caption のリンクは、panel が URL を確かめずに開く) | markdown の節に `[字](URL)` で書く |
| PR の番号を「いま」の箇条書きに並べる | 進み具合の木の、その PR を出した子の行の下に行で足す (状態の札とリンクが付く) |
| panel の SVG に CSS や SMIL の動きを書き足す (panel では動かない) | 動きは marks に書く。panel の外で動かす写しには `pjp hub bake` が焼く |
